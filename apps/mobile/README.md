# @dos/mobile

The DOS field-staff app — React Native **bare** (not Expo managed), per the
product's mobile decision (see `docs/technical-log/phase-2.md`), targeting
Android and iOS.

## Getting started

This app needs native toolchains this container doesn't have (Android SDK /
Xcode) — the commands below are for a machine that does.

```bash
pnpm install
pnpm --filter @dos/mobile ios      # first run: bundle exec pod install inside ios/
pnpm --filter @dos/mobile android
```

`pnpm --filter @dos/mobile start` runs the Metro bundler on its own.

## Structure

```
App.tsx                  Root component: safe-area + navigation providers
src/
  navigation/
    RootNavigator.tsx      The app's route stack (React Navigation)
  screens/
    HomeScreen.tsx          Placeholder landing screen
android/, ios/            Native projects generated by the React Native CLI
```

## Fase 2 scope note

This is a navigation **scaffold**, not the finished app — per the roadmap,
the real field-staff screens (today's jobs, clock in/out, client details)
land in Fase 6 (App móvil). There is no auth integration yet; that follows
the same pattern built for `apps/web` (`src/api/client.ts`,
`src/context/AuthContext.tsx`) once Fase 6 starts.

Native builds (`pnpm android`/`pnpm ios`) were not run as part of this
scaffold — this container has no Android SDK or Xcode. `pnpm build`
(`tsc --noEmit` plus a Metro Android bundle written to `dist/`) is used
instead to verify the TypeScript and the JS bundle compile correctly
without needing a device, emulator, or native toolchain.

## Scripts

- `pnpm start` — start the Metro bundler.
- `pnpm android` / `pnpm ios` — build and run on a connected device/emulator.
- `pnpm build` — type-check and produce a release JS bundle (`dist/`).
- `pnpm lint` — lint this app.
- `pnpm test` — run the Jest test suite.
