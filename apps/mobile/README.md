# @dos/mobile

The DOS field-staff app — React Native **bare** (not Expo managed), per the
product's mobile decision (see `docs/technical-log/phase-2.md`), targeting
Android and iOS. Real screens (Fase 6): sign in, see your assigned jobs,
open one to see the client/address/services, and clock in/out.

## Getting started

This app needs native toolchains this container doesn't have (Android SDK /
Xcode) — the commands below are for a machine that does.

```bash
pnpm install
pnpm --filter @dos/mobile ios      # first run: bundle exec pod install inside ios/
pnpm --filter @dos/mobile android
```

`pnpm --filter @dos/mobile start` runs the Metro bundler on its own.

Point it at a running `apps/api` by editing `src/api/config.ts`
(`API_BASE_URL`) — `localhost` works from an iOS simulator; an Android
emulator needs `10.0.2.2` (its alias for the host loopback interface)
instead.

## Structure

```
App.tsx                          Root component: safe-area + auth + navigation providers
src/
  api/
    config.ts                      API_BASE_URL
    client.ts                      Typed fetch wrapper (Authorization header, ApiError)
  auth/
    tokenStorage.ts                Keychain/Keystore-backed token persistence
  context/
    AuthContext.tsx                Session state: login, org selection, logout, restore-on-launch
  navigation/
    RootNavigator.tsx              Auth-gated stacks (unauthenticated vs. authenticated)
  screens/
    LoginScreen.tsx
    SelectOrganizationScreen.tsx    Multi-membership accounts only
    JobsListScreen.tsx              The caller's assigned jobs
    JobDetailScreen.tsx             Client/address/services + clock in/out
  types/
    api.ts                         Hand-written types for the API responses this app consumes
android/, ios/                   Native projects generated by the React Native CLI
```

## Auth model

Unlike `apps/web` (access token in memory only; refresh token in an
httpOnly cookie the SPA never touches), this app persists **both** tokens
itself in the platform secure storage (`react-native-keychain` — iOS
Keychain / Android Keystore), per
[`docs/architecture/auth.md`](../../docs/architecture/auth.md)'s mobile
token-storage section: cookies aren't a natural fit for a native app's
HTTP client. On launch, a stored session is restored by immediately
rotating the refresh token (`POST /auth/refresh`) rather than trusting a
possibly-expired stored access token (15 minute lifetime — the app is
very likely to have been closed longer than that between launches).
Multi-organization accounts get a real selection screen (unlike the web
scaffold, which currently just shows an error for that case).

## What is and isn't verified

This container has no Android SDK or Xcode, so native builds
(`pnpm android`/`pnpm ios`) were not run — `pnpm build` (`tsc --noEmit`
plus a Metro Android JS bundle to `dist/`) is used instead, which
verifies the TypeScript and that every import resolves and bundles, but
**not** that `react-native-keychain`'s native module links and works on
a real device. Screen logic and the API client are unit/component-tested
under Jest (`pnpm test`); a couple of Keychain-dependent tests use a
manual mock (`__mocks__/react-native-keychain.js`) since no native
Keychain exists under Jest either. See
[`docs/technical-log/phase-6.md`](../../docs/technical-log/phase-6.md)
for the full account of what was and wasn't exercisable in this sandbox.

## Scripts

- `pnpm start` — start the Metro bundler.
- `pnpm android` / `pnpm ios` — build and run on a connected device/emulator.
- `pnpm build` — type-check and produce a release JS bundle (`dist/`).
- `pnpm lint` — lint this app.
- `pnpm test` — run the Jest test suite.
